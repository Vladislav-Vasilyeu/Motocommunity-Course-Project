## Исправления по воспроизводимым ошибкам

1. PATCH профиля терял роль в ответе. Добавлено поле `role`; обновление профиля больше не убирает данные о полномочиях из AuthProvider.
2. Две одновременные регистрации одного email давали 201 и 500. Обработка уникального ограничения теперь возвращает 409 EMAIL_IN_USE.
3. Слишком большой JSON превращался в 500. Теперь это 413 PAYLOAD_TOO_LARGE в стандартной форме, с переводом для клиента.
4. Некорректные точки поездки (`null`, пустые или булевы координаты) приводили к 500; дата `null` интерпретировалась как эпоха. Теперь используются проверка типа даты и нормализация координат, неверный ввод возвращает 400 INVALID_TRIP. Числовые строки координат сохраняются как числа.
5. Конкурентные вступления в поездку иногда приводили к 500. Вставка с `skipDuplicates` сохраняет одно участие и возвращает 204 для повторных запросов.
6. Вступление в отсутствующее сообщество приводило к ошибке внешнего ключа и 500. Добавлен 404; конкурентное повторное вступление также не дублирует участника.

После исправлений наборы повторены целиком. Проверка сохранённых даты и координат поездки усилена по замечанию ревьюера. Frontend/backend build и `git diff --check` выполнены успешно. Независимый ревьюер GPT-6.1 Sol не нашёл подтверждённых регрессий в production-правках; разработчики тестов также работали на GPT-6.1 Sol.

## Ограничения и следующие задачи

Сценарии проверяют реализованные HTTP-контракты. У поездок нет полного редактирования/удаления, у сообществ нет передачи владения и полного CRUD, у друзей нет удаления/отзыва заявки; эти операции не выдаются за пройденные. Развёрнутые ограничения указаны в модульных документах. Сообщения работают через HTTP, без Socket.IO; групповые чаты и медиа не добавлялись этой работой.

Не проверены личный Google OAuth consent/token exchange, реальные мобильные устройства, экранный диктор, нагрузка, отказоустойчивость внешнего провайдера во всех вариантах и production-развёртывание. Эти ограничения не заменяются зелёными API-тестами.
