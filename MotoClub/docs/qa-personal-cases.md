# QA: сообщения, обслуживание и уведомления — задача #68

Дата: 24 ноября 2026. Автоматизированный HTTP-сценарий: `server/scripts/qa/personal.mjs`.

## Безопасный запуск

Сценарий намеренно создаёт данные. Использовать только с отдельным локальным API и одноразовой базой, подготовленными координатором; рабочую базу не использовать.

```powershell
$env:QA_API_URL='http://localhost:4314'
$env:QA_ALLOW_WRITES='1'
node MotoClub/server/scripts/qa/personal.mjs
```

Общий клиент запрещает запуск без обеих переменных и с нелокальным URL. Каждый запуск регистрирует три новых UUID-аккаунта и использует сессионные cookie `motoclub_session`. Два созданных мотоцикла удаляются после успешного выполнения. Аккаунты, диалоги, сообщения, дружба и уведомления остаются в одноразовой базе; при сбое могут остаться также мотоциклы. Очисткой всей временной базы управляет координатор.

## Проверенные сценарии

1. Гость получает 401 на чтение/отправку сообщений, все четыре операции журнала обслуживания, чтение уведомлений и отметки прочтения.
2. Сообщения: запрет себе, отсутствующий/некорректный получатель, пустой текст, пробелы, неверный тип, превышение 2000 символов, некорректный cursor. Текст обрезается по краям, 2000 символов принимаются, оба участника видят сохранённую историю.
3. Третий пользователь не видит чужой диалог в списке или истории; cursor из чужого/другого диалога не открывает сообщения и возвращает 400.
4. После двух последовательных и 104 одновременных отправок существует один диалог пары; страницы истории содержат 50/50/6 сообщений, сохраняют порядок `(createdAt, id)` и не имеют пропусков или дубликатов. Последнее сообщение списка диалогов соответствует истории. Отдельный диалог не смешивается с первым.
5. Обслуживание: создание, список, частичное изменение, нулевые значения, очистка nullable-полей, сортировка по дате, удаление и повторное обращение к удалённой записи. Високосная дата `2024-02-29`, дробная стоимость `125.35` и верхняя допустимая стоимость `9999999999.99` сохраняются точно в JSON-ответе.
6. Чужой пользователь получает 404 при чтении/создании/изменении/удалении обслуживания. Владелец также не может изменить или удалить запись через ID другого мотоцикла. Записи после отказов не меняются; публичный профиль не содержит приватных заметок.
7. На POST и PATCH проверены пустое/длинное название, невозможные даты, год 0000, timestamp вместо даты, отрицательный/дробный/слишком большой/строковый пробег, отрицательная/слишком точная/слишком большая/строковая стоимость, длинные/нестроковые заметки. Пустой PATCH, массив и неизвестные поля отклоняются. JSON `null` отклоняется парсером с `INVALID_JSON`; ошибки полей — `INVALID_MAINTENANCE_RECORD`.
8. Уведомления о сообщениях создаются только получателю: проверены количество, тип, actor, ссылка `/messages/:actorId`, `readAt` и совпадение unreadCount с фильтром непрочитанных.
9. Заявка в друзья создаёт `FRIEND_REQUEST`, принятие — `FRIEND_REQUEST_ACCEPTED`; обе ссылки ведут на `/friends`, actor соответствует инициатору события.
10. Отметить одно уведомление может только получатель: гость получает 401, другой пользователь и отсутствующий ID — 404. Повторное чтение сохраняет исходное время прочтения; новый HTTP-клиент с той же cookie видит сохранённое состояние и уменьшенный unreadCount.
11. «Прочитать все» влияет только на текущего получателя; списки двух других пользователей полностью сохраняются. Новое сообщение после этой операции создаёт ровно одно непрочитанное уведомление, состояние сохраняется при новом HTTP-клиенте.

## Результат и границы

На изолированном API `http://localhost:4314` выполнен полный прогон: **13 PASS, 0 FAIL**. Подтверждённых дефектов production-кода в этом наборе не обнаружено. Первый диагностический запуск остановился на неверном ожидании сценария для JSON `null`; ожидание исправлено согласно действующему глобальному обработчику, затем весь набор повторён с новыми аккаунтами.

`npm --prefix MotoClub/server run build` — успешно (Prisma generation и TypeScript). Production-код и публичные API-контракты не изменены.

Это проверка HTTP API с повторным чтением данных: WebSocket/Socket.IO в текущей реализации отсутствует и не добавлялся. Фильтр «Непрочитанные» реализован на клиенте; сценарий проверяет серверные поля и эквивалентный предикат `!readAt`, а не взаимодействие с кнопкой в браузере. Визуальная доступность, клавиатура, адаптивность, таймеры polling и поведение при сетевом обрыве этим скриптом не проверялись. Для проверки равных timestamps используется реальная конкурентная отправка, но точное совпадение времени не навязывается базе.
