## Автоматизированный API-сценарий

`server/scripts/qa/travel.mjs` использует общий `client.mjs`, реальные cookie `motoclub_session` и три независимых синтетических аккаунта. Запуск разрешён только против явно указанного локального одноразового API. Сценарий создаёт записи; удаление всей тестовой базы выполняет координатор, скрипт не очищает существующие данные.

```powershell
$env:QA_API_URL='http://localhost:4314'
$env:QA_ALLOW_WRITES='1'
node server/scripts/qa/travel.mjs
```

Покрытие:

- Гостевые каталоги, запрет защищённых изменений без cookie, защита избранного.
- Создание маршрута, автор, публичная детализация, порядок трёх точек и координаты.
- Поиск по названию/описанию без учёта регистра и пустая выдача.
- Конкурентное идемпотентное добавление в избранное, удаление, изоляция аккаунтов.
- Ошибки отсутствующих маршрутов и проверка числа/типов/диапазона точек.
- Создание полезного места с нулевыми координатами, публичные данные и фильтр категории.
- Создание поездки, публичная детализация для карты, порядок остановок, дата и число участников.
- Конкурентное вступление, изоляция `isJoined`, публичный список участников без email/секретов.
- Запрет удаления участников постороннему и самому участнику; исключение организатором.
- Выход только из собственного участия, повторный выход и отсутствующие поездки.
- Некорректные точки/координаты поездки должны возвращать 400 `INVALID_TRIP`, без 500.

Первый запуск против изолированного API прошёл первые 10 групп и обнаружил 500 при трёх одновременных вступлениях одного пользователя. Дополнительная HTTP-проверка обнаружила 500 для точки `null` и координат `null`, пустой строки и `true`. Координатор исправил нормализацию координат через `parseCoordinate`, проверку даты и идемпотентное вступление через `createMany` с `skipDuplicates`.

Повторный запуск после сборки и перезапуска изолированного API: **15/15 групп PASS**. Проверены также отсутствующие поля, массив вместо точки, дата `null`, повторное исключение/выход и три параллельных вступления. `node --check server/scripts/qa/travel.mjs` и `npm --prefix server run build` прошли успешно. Frontend в рамках этих файлов не изменялся; браузерные проверки ниже ещё не выполнялись этим сценарием.

## Ручные UI-сценарии — ожидают выполнения

Перечисленные проверки являются планом, а не утверждением об успешном прохождении браузерного теста.

1. Гость: `/routes`, поиск, пустая выдача, детали и переход к `/map?route=…`; вместо сохранения доступен вход. Гостевой фильтр избранного показывает приглашение войти.
2. Пользователь A: создать маршрут из трёх точек; проверить порядок и координаты в деталях и списке остановок карты. Сохранить в избранное, обновить страницу, удалить. Пользователь B не видит маршрут в своём избранном.
3. Создать поездку со стартом, промежуточной остановкой и финишем; удалить промежуточную остановку формы и добавить заново; проверить дату и порядок после сохранения. Открыть карту выбранной поездки: показаны только её точки и соединяющая их по порядку линия.
4. Пользователь B вступает, обновляет страницу, видит своё участие; пользователь C его не наследует. Проверить счётчик, раскрытие участников, исключение организатором и выход участника.
5. Для отсутствующих ID маршрута/поездки показываются ошибки с повтором. При отказе `/api/places` и `/api/trips` доступны ошибки/повтор; после восстановления загрузка возобновляется. При пустых местах/поездках показаны пустые состояния.
6. Без ключа Google Maps остаются места и остановки, видна честная информация о недоступной карте. При заблокированной сети/ошибке ключа/таймауте есть сообщение и повтор; список продолжает работать.
7. При настоящем Google Maps: дождаться загрузки тайлов; проверить маркеры и подписи, нумерацию остановок, порядок полилинии, масштаб выбранного пути, карточку маркера, поиск/категории мест, кнопку «На карте» и переход фокуса. HTML в названиях/описании отображается текстом, не выполняется.
8. Проверить Tab/Shift+Tab/Enter/Space для форм, фильтров, `<details>`, кнопок и ссылок; видимый фокус и отсутствие ловушки. Проверить ширины 360/390/768/1024/1440, светлую/тёмную темы и RU/EN, перенос длинных названий и формат даты.
9. На карте изменить выбранный маршрут через внутреннюю навигацию, затем вернуться: старые маркеры/линии и выделение места не остаются. Переключить тему; после смены языка проверить предлагаемую перезагрузку элементов провайдера.

## Границы подтверждения

Настоящий Google Maps с разрешённым ключом, биллингом, сетевой загрузкой тайлов и интерактивными маркерами данным API-сценарием не проверяется. Подмена Google не является подтверждением работы внешнего провайдера.

Текущий API поездок поддерживает создание, чтение, вступление/выход и исключение участников организатором. Редактирование и удаление поездки (PATCH/DELETE сущности), отмена и завершение не представлены существующими API/UI; полный CRUD этим сценарием не заявлен. Решение о расширении функциональности остаётся координатору.
